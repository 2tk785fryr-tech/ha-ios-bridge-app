## Items

1. **Naps and bedtime pending.** Found by the Home Assistant chat while reviewing the 0.4.8
   blueprint edit: the integration's automatic report "in bed 10 minutes with bedtime pending and
   no RUN_BEDTIME" doesn't check for a nap, so a nap taken while tomorrow's alarms are set files a
   false report.
   - **The blueprint now handles naps (read 31 Oct, read-only):** `automation.bedtime_nudge` uses
     **Bedtime Nudge v1-05** (`bedtime_nudge_v1-05.yaml`). Since v1-03/v1-04:
     - **Bedtime pending** passes the window check at any hour but only earns the **tap-to-run**
       push, never the auto-run (Michael's call: a lie-down with the door shut would otherwise
       sweep the house, maybe with Seth downstairs).
     - **The auto-run window** runs from its usual start to **2 h before the first alarm**, read
       from the next-alarm sensor's `alarm_times`, within 14 h of the start. That would have
       auto-run the 31 Oct 4:01 bedtime.
     - **Naps:** while `input_boolean.napping` is on, nothing is sent at any hour, checked before
       the warning and again before the push; it only blocks for 4 h after it turned on, in case
       "nap ended" is lost. Bedtime Bridge turns it on when a nap is set at home and off when the
       nap ends.
     - **One bedtime per night (v1-05):** once the routine has run, nothing more is sent before
       the cut-off.
     - **The nap ending isn't a trigger:** staying in bed after the nap alarm sends nothing until
       you get back into bed or the door closes.
   - So `bedtime_pending` itself doesn't need to change for naps (the earlier proposal to pause it
     during a nap is dropped). What's left here:
   - **Fix (integration):** the automatic report skips naps, the same way the blueprint does: no
     report while a nap is on (nap alarms set, or the napping helper on for less than 4 h). It
     already expects one report on a tap-to-run night that's never tapped (correct: bedtime didn't
     run).
   - **The nap that turns into the night** (Michael's case: you nap, don't get up, and it's
     bedtime). When the nap ends you're already in bed, so nothing happens. **To decide:**
     a. **The blueprint picks it up (recommended):** a hand-off to the Home Assistant chat: the
        napping helper turning off becomes a trigger that runs the usual checks (in bed, door
        shut, not already run tonight). Inside tonight's window it auto-runs; outside, with
        bedtime pending, it's the tap-to-run push. Nothing in Bedtime Bridge changes, and the
        blueprint's rules (Seth, one per night) stay in one place.
     b. **Home Assistant sends RUN_BEDTIME itself** 10 min after the nap ended while still in bed.
        Simpler, but it skips the blueprint's checks.
     c. **Nothing automatic:** the bar's Good night is there (alarms set), and the report notes it.

2. **The 0.4.8 hand-off gave the wrong entity id for bedtime pending.** The blueprint's notes:
   the sensor is `binary_sensor.master_bedroom_bedtime_bridge_bedtime_pending`, not
   `binary_sensor.bedtime_bridge_bedtime_pending`, because the Bedtime Bridge device was moved to
   the Master Bedroom area before 0.4.8 added it, and Home Assistant prefixes new entity ids with
   the area. The blueprint uses the right id; the hand-off would have pointed at nothing.
   - **Fix:** correct `docs/ha-handoffs-v0.4.8.md` (and the README) to say "read the id back"
     with the real one as the example; and from now on hand-offs name an entity by what it is
     ("Bedtime Bridge → Bedtime pending") plus the id as read from Home Assistant, not the id
     the integration would pick on a fresh install.
   - The section 2 blueprint edits in that hand-off are superseded by v1-05; say so there.

3. **The Lock Screen widget doesn't show a nap.** Testing 31 Oct with tomorrow's alarms set and a
   nap on: the Lock Screen showed the morning's alarms, not the nap.
   - **Cause (read-only):** the widget reads the app's alarm snapshot, which holds the regular
     alarms and temporary alarms but not nap alarms (`NextAlarmSnapshot`: `alarmTimes` and
     `temporaryAlarms`, no naps). So "next alarm" skips the nap, in every size (Lock Screen
     rectangular, circular and inline, and the Home Screen sizes), and the medium/large timeline
     doesn't list it either. Only the app's bar shows "Napping · up at …".
   - **Fix:** the snapshot carries the nap's alarms, and while a nap is on the widget leads with
     it: **"Nap · up at 3:20"** (rectangular and small), "3:20" with a nap icon (circular), "Nap
     up 3:20" (inline), with the morning's first alarm under it where there's room ("Then 5:00
     tomorrow"). The timeline lists the nap alarms first. It goes back to the morning once the
     nap ends. Snoozing a nap shows "Snoozing · rings 3:29" as it does for the morning.
   - **To decide:** a nap **Live Activity** too (Lock Screen and Dynamic Island: "Napping · up
     at 3:20" with a countdown and End nap), like wind-down's? Or the widget is enough.
